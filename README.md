# بهسا دیجیتال — نسخه Next.js با CMS اختصاصی

این پوشه نسخه جدید سایت است. پروژه Vite قبلی در پوشه والد **دست‌نخورده** مانده تا بعد از تأیید، جایگزین شود.

## معماری

| لایه | انتخاب | دلیل |
|---|---|---|
| فریم‌ورک | Next.js 16 (App Router) + React 19 | رندر سمت سرور؛ هر صفحه URL واقعی و HTML کامل دارد |
| استایل | Tailwind CSS 4 (همان توکن‌های طراحی قبلی) | ظاهر سایت بدون تغییر |
| دیتابیس | PostgreSQL + Drizzle ORM | سبک، بدون موتور باینری، مایگریشن SQL خوانا |
| CMS | پنل اختصاصی `/admin` داخل همان اپ (Server Actions) | بدون CMS خارجی و بدون backend مستقل |
| محتوای صفحه | منو + بخش‌های صفحه در دیتابیس، با رجیستری بخش‌ها در کد | انعطاف برای کسب‌وکار، بدون تبدیل‌شدن به page-builder |
| احراز هویت | نشست در دیتابیس + کوکی httpOnly + bcrypt | بدون سرویس ثالث |
| رسانه | تصاویر داخل PostgreSQL (`bytea`) | یک بکاپ دیتابیس = بکاپ کامل محتوا |

نیازی به Django، Nest یا backend مستقل پیدا نشد؛ همه نیازها (خواندن/نوشتن DB، آپلود، احراز هویت) با Server Actions و Route Handlerهای Next.js پوشش داده می‌شود.

### چه چیزی در CMS است و چه چیزی در کد
- **CMS (دیتابیس):** منوی سایت (سرفصل‌ها و زیرمنوها)، بخش هیرو (ویدئو/تصویر/متن/دکمه‌ها)، نوار «مخاطبان بهسا»، بخش‌های صفحه اصلی (چالش‌ها، پلتفرم، راهکارها، امکانات، مخاطبان، دستاوردها، عنوان بخش‌های نظرات/مقالات/پرسش‌ها و نوار پایانی)، مقالات (با پیش‌نویس، زمان‌بندی، پیش‌نمایش)، دسته‌ها، پرسش‌های متداول، نظرات مشتریان، نام مشتریان، رسانه‌ها، اطلاعات تماس و تنظیمات، سئوی اختصاصی هر صفحه، کاربران پنل (نقش مدیر/ویرایشگر).
- **کد:** چیدمان و استایل، آیکون‌ها و توکن‌های طراحی، دادهٔ نمونهٔ داشبورد صفحه اصلی، متن صفحات «خدمات» و «درباره ما»، محتوای تفصیلی قابلیت‌ها (`src/content/capabilities.ts`) و لینک‌های متقاطع قابلیت ⇄ راهکار.

### مدل محتوا (فاز ۲)
| جدول | نقش |
|---|---|
| `nav_items` | درخت منو (سرفصل + زیرمنو): عنوان، آدرس، ترتیب، نمایش/پنهان، تب جدید، نوع منو |
| `content_sections` | هر بخش قابل‌ویرایش صفحه: عنوان، متن، دکمه، تصویر دسکتاپ/موبایل، ویدئو، نمایش/پنهان |
| `content_items` | کارت‌ها/دکمه‌ها/شرکت‌های هر بخش: عنوان، توضیح، آیکون، برچسب، لینک، فهرست، تصویر، ترتیب |

فهرست بخش‌ها و اینکه ویرایشگر برای هر بخش چه فیلدهایی می‌بیند، فقط در `src/content/sections.ts` تعریف می‌شود؛
همان فایل مقادیر پیش‌فرض (محتوای فعلی سایت) را هم نگه می‌دارد و `npm run db:seed` از روی آن دیتابیس را پر می‌کند.
اگر ردیف یک بخش در دیتابیس نباشد، سایت همان مقدار پیش‌فرض را نمایش می‌دهد؛ پس نصب تازه هم بدون محتوا نمی‌ماند.

**مرز CMS:** ویرایشگر به HTML یا CSS خام دسترسی ندارد. آیکون‌ها از فهرست ثابت انتخاب می‌شوند، لینک‌ها اعتبارسنجی می‌شوند
(`javascript:` و `data:` رد می‌شوند) و تنها نشانه‌گذاری مجاز در عنوان‌ها `*کلمه*` است که آن را برجسته می‌کند.

## راه‌اندازی

```bash
cp .env.example .env          # DATABASE_URL و NEXT_PUBLIC_SITE_URL را تنظیم کنید
npm install
npm run db:migrate            # ساخت جدول‌ها
npm run db:seed               # انتقال محتوای فعلی سایت به دیتابیس (قابل اجرای مجدد)
ADMIN_PASSWORD='…' npm run admin:create   # ساخت اولین مدیر (یا بازنشانی رمز)
npm run dev                   # http://localhost:3000  و  /admin
```

پس از هر `git pull` که اسکیما را تغییر داده باشد: `npm run db:migrate && npm run db:seed` (هر دو idempotent هستند و محتوای ویرایش‌شده را بازنویسی نمی‌کنند).

### Production
```bash
npm run build
cp -r public .next/standalone/ && cp -r .next/static .next/standalone/.next/
cd .next/standalone && node server.js
```
یا با Docker: `docker build -t behsa-web .` و اجرای کانتینر با `DATABASE_URL`، `NEXT_PUBLIC_SITE_URL`.

پشت Nginx اجرا کنید و `X-Forwarded-For` را تنظیم کنید؛ محدودیت تلاش ورود بر اساس IP از این هدر استفاده می‌کند.
برای محیط تست `SITE_NOINDEX=true` بگذارید تا گوگل ایندکس نکند.

## SEO
- URLهای واقعی به‌جای `#/…`؛ لینک‌های قدیمی hash خودکار به مسیر جدید هدایت می‌شوند و `/products` با 308 به `/product` می‌رود.
- Metadata API برای هر صفحه: title، description، canonical، Open Graph، Twitter Card و robots. مقدار سئوی ثبت‌شده در پنل همیشه بر مقدار پیش‌فرض اولویت دارد.
- `sitemap.xml` پویا (صفحات + ۴۰ صفحه راهکار/صنعت + مقالات منتشرشده با lastModified؛ صفحات noindex حذف می‌شوند)، `robots.txt`، `manifest.webmanifest`، فید RSS در `/articles/feed.xml`.
- JSON-LD: Organization، WebSite، FAQPage، BlogPosting، Blog، BreadcrumbList و Service.
- پیش‌نویس‌ها 404 هستند؛ پیش‌نمایش فقط برای کاربر واردشده و با `noindex`.
- پنل مدیریت با `X-Robots-Tag: noindex` و بدون کش.
- هدرهای امنیتی، فونت self-hosted و کش immutable برای رسانه‌ها.

## کش و به‌روزرسانی
صفحات عمومی per-request رندر می‌شوند، ولی کوئری‌ها با `unstable_cache` کش و تگ‌گذاری شده‌اند. هر ذخیره در پنل با `updateTag` همان تگ را منقضی می‌کند، پس تغییرات بلافاصله دیده می‌شوند و `next build` به دیتابیس نیاز ندارد. مقالات زمان‌بندی‌شده حداکثر یک ساعت بعد از زمان انتشار ظاهر می‌شوند.

## ساختار
```
src/app/(site)/        صفحات عمومی
src/app/admin/         پنل CMS و Server Actions (_actions/)
src/app/sitemap.ts     robots.ts · manifest.ts · media/[id] · api/preview
src/db/schema.ts       اسکیمای PostgreSQL
src/content/sections.ts رجیستری بخش‌های قابل‌ویرایش + محتوای پیش‌فرض
src/content/navigation.ts انواع منو + منوی پیش‌فرض + لینک‌های متقاطع
src/lib/cms.ts         لایه خواندن کش‌شده (منو، بخش‌ها، مقالات، تنظیمات)
src/lib/seo.ts         buildMetadata
src/lib/auth.ts        نشست، ورود، محدودیت تلاش
src/views/ src/components/   کامپوننت‌های منتقل‌شده از نسخه Vite
drizzle/               مایگریشن‌ها · scripts/ seed و ساخت مدیر
```

## بررسی صحت
```bash
npm run typecheck   # tsc --noEmit
npm run check       # صحت مدل محتوا و اعتبارسنجی لینک‌ها (بدون دیتابیس)
npm run build       # بیلد پروداکشن
```

## مراحل بعدی پیشنهادی
1. اجرای موازی روی ساب‌دامین staging با `SITE_NOINDEX=true` و مقایسه ظاهری.
2. جایگزینی دامنه اصلی، ثبت sitemap در Google Search Console.
3. انتقال متن صفحات «خدمات» و «درباره ما» به همین مدل بخش‌ها (فقط افزودن ورودی در `src/content/sections.ts` و خواندن آن در همان view).
